Reviewer: Codex (`codex exec --sandbox read-only`), on the design section "Step 3 design (3b, 3c, 3d)" of `docs/PLAN_futhark_kingdom.md`, with `gen_tables.py`, `src/futhark_sig.rs`, `src/futhark_table.rs`, `src/futhark.rs` and the four `interface.tsv`. Its findings verbatim, then the disposition of each.

## Dispositions

## The review, verbatim

1. **Blocker — views still share one `Ty` namespace.** `FutharkFamily::Shape` maps every view’s dual index to `Ty::Futhark(index)`; it has no view identity. Two live views can therefore give `Ty::Futhark(0)` different meanings. This breaks multi-typed GEP if views/kingdoms coexist. Evidence: [src/futhark_table.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_table.rs:35), [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:248). Fix: allocate a per-view type family/namespace (or forbid composition structurally and enforce that at the engine boundary).

2. **Major — D1’s “context-free” derivation changes the rule it claims to preserve.** Today `free` is `classes - (rank1 ∪ scalar)`—i.e. every rank-2+ class is context-free because the current row set cannot produce it. D1 instead infers it from whether *any master template* has a rank≥2 output. Adding a future rank-2 producer can silently contextualise existing input classes and renumber/retype tables. Evidence: [gen_tables.py](/Users/andrewmorgan/Dev/gamakon/fuller/kingdoms/futhark/gen_tables.py:1900), [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:111). Fix: make context-freedom an explicit class property, or derive it per concrete class from instantiated producers and reject a change to an existing view unless its pinned output is unchanged.

3. **Major — no current `sig_rows` loop is intrinsically inexpressible, but D1 underspecifies the ordering algorithm needed to prove byte identity.** The difficult loops are expressible: `C;D:rank1;D2:rank1` for histogram, `C;D:rank1;Y:rows(...)` for `row.*`, `C;V:vars(...)`, and the final `X:free;I:inputs(...)` block. However “consecutive rows that share their first quantifier” is ambiguous when adjacent templates share a quantifier text but bind differently or one has a shorter scope; it is not a serialization format for the exact loop tree. Evidence: [gen_tables.py](/Users/andrewmorgan/Dev/gamakon/fuller/kingdoms/futhark/gen_tables.py:1927), [gen_tables.py](/Users/andrewmorgan/Dev/gamakon/fuller/kingdoms/futhark/gen_tables.py:1976), [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:109). Fix: encode explicit block begin/end IDs (or a parent block ID), and add a witness that compares the expanded `(template-ref, bindings)` stream—not only final TSV bytes.

4. **Major — the proposed view format is incompatible with the current Rust parser.** `signature()` accepts only `input`, `size`, `output`, `depth`, and `dims`; it rejects `master`, `element`, `families`, and `literals`. “Changes little” is false. Evidence: [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:276), [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:120). Fix: specify and implement a `ViewSpec` parser separately; derive `Signature` from it.

5. **Major — the sniffer’s family rule is unsound.** Searching only the typed entry body misses `%` in a helper reachable from `main` (the histogram wrapper has `main -> bins`, with `%` in `bins`). Searching the full `futhark dev -t` output instead sees prelude code and admits false families. It also treats syntactic `%` as proof that the kingdom’s special “mod by a positive dimension” row is the relevant operation. Evidence: [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:151); current histogram reference requires both `hist` and `mod` [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:210). Fix: parse typed AST/name-resolved IR, traverse the entry’s reachable call graph, and classify primitive operations semantically; make family policy explicit rather than inferred from text.

6. **Major — `futhark dev -t` is a brittle serialization interface, not a parser API.** In 0.28.1 it emits the entire elaborated prelude plus normalized declarations; parsing one formatted entry line depends on printer spelling, parentheses, inferred-size syntax, and version. Evidence: [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:151). Fix: pin the compiler version and parse a stable machine-readable compiler interface if available; otherwise parse source with the Futhark parser and use `dev -t` only as an independently checked oracle/snapshot.

7. **Major — size-input detection is incomplete and can misclassify legal signatures.** “Scalar `i32` appearing as `i64.i32 p`” only detects the direct cast form; it does not define behaviour for derived size expressions, sizes inferred through helpers, repeated dimensions, or scalar `i32` values used both as a value and in a size expression. Existing runtime assumptions also require every size be positive. Evidence: [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:151), [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:319). Fix: extract dimension binders and their provenance from typed AST, accept only a documented direct-parameter subset for Step 3, and reject all other forms with diagnostics.

8. **Major — the regression’s random-gene test does not prove “same genes ⇒ same programs.”** Two hundred random genes can miss changed alphabet entries, constant lengths, symbol IDs, and unreachable-but-selectable layout cells. The byte-equal tables are the useful proof only if parser/order/rendering contracts are also compared. Evidence: [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:157). Fix: assert byte equality of every consumed artifact, equality of `FutharkKingdom` rows/duals and `KingdomContract`/constant lengths/layout alphabets, then exhaustively render every row and constant index. Keep randomized expression tests as supplementary.

9. **Major — caching/lifetime ownership is not designed.** Today `Instance` and `Problem` are `Copy` and embed `&'static str`; `load()` returns an owned `FutharkKingdom`, while `Bridge` independently parses another artifact. A runtime-owned `View` cannot simply be placed in that `Copy` instance, and an unspecified process cache can yield separate kingdom/bridge/signature instances. Evidence: [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:37), [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:1418), [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:141). Fix: keep `Instance` as a static spec handle; use one per-instance `OnceLock<Result<ViewCache, String>>`, where `ViewCache` owns view text, parsed signature, kingdom, and bridge. Return references or `Arc<ViewCache>` consistently.

10. **Major — f32 invalidates the stated semantic/e-graph/interpreter assumptions.** Current interpreter, binary codec, constants, equality, and operations are i32-only; the e-graph justification relies on exact wrapping-i32 identities. Floating addition/multiplication/reductions are not associative under IEEE rounding, and NaN/signed-zero make naïve `min`/`max`, equality, and rewrite assumptions unsafe. Evidence: [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:363), [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:763), [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:166). Fix: use typed values with raw f32-bit binary I/O; define NaN/-0 comparison policy; disable non-bit-exact float rewrites; test CPU/GPU/reduction semantics separately.

11. **Major — tuple names are not structurally parseable, and tuples exceed the current value model.** `t.<c1>.<c2>` is ambiguous when component classes themselves contain dots (`t.a.n.a.m`); current parsing relies on dotted string prefixes. `Array` represents one i32 array, so neither tuple inputs/outputs nor tuple loop state can be evaluated, compared, fingerprinted, or encoded as proposed. Evidence: [src/futhark_sig.rs](/Users/andrewmorgan/Dev/gamakon/fuller/src/futhark_sig.rs:363), [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:167). Fix: make class/type an AST with an injective TSV encoding; introduce recursive typed `Value`/signature schemas before adding tuple rows.

12. **Minor — rules are still hand-derived in a rule that is not represented by D1.** Current `sig_egraph_texts` hard-codes which operators commute/associate and separately gates array rules on `map2.min`; D1’s `rules.tsv` sketch does not specify direction, variable binding, required operators per rule, or float eligibility. Evidence: [gen_tables.py](/Users/andrewmorgan/Dev/gamakon/fuller/kingdoms/futhark/gen_tables.py:2060), [PLAN](/Users/andrewmorgan/Dev/gamakon/fuller/docs/PLAN_futhark_kingdom.md:107). Fix: put complete rule schemas—including direction, all dependencies, semantic domain, and NaN policy—in the master, with an independent rule-soundness witness.
