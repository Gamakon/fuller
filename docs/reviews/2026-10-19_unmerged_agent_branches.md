What it does (the emitter's speed, the user flow's step 2 gate). Two renderer optimisations:
1. Shared loads (`Renderer::shared_loads`, `share_key`, `run_t`, `run_items`, `reads_writes`, `shareable_load`, `copy_lets`, `Scope.shared`/`Scope.lets`): a load that a straight-line run reads two or more times while its value holds (no write to a register it reads, no store, no control flow or barrier between) is written once as `let ld<n> = ...;` and named at each use; lets in unrolled copies are renamed `ld<n>_<j>`.
2. Early exit (`Renderer::early_exit`): when every write of the kernel is a `store.h_safe`/`store.h_mirror` inside an `if` at cells of one origin, and there is no atomic, workgroup memory, barrier or subgroup operation, the thread's `guard(row0, col0)` is written as `if (!(guard)) { return; }` at the top, which is what the shipped and blocked Gram kernels do.
Tests added: `renderings_share_repeated_loads_and_exit_early_and_read_back` (nluca k01 and gram shipped/blocked: counts of the shared text, read back to the same tree, `same_values` on the CPU), `a_shared_load_ends_where_its_index_register_is_written`, and a `scratch_random_text` module with no assertions (prints counts only) that should not be merged as is (Rules.md: scratch work belongs in tmp/). `rules.rs` test line changed to expect `let ld1 = wg_va[...]` and `ld1.w`.

No later commit touching `render.rs` since 0d74f08 adds load sharing or an early exit (the list from `git log 0d74f08..paired-fitness -- src/wgsl/render.rs` is all reader/sampler/kingdom row fixes).
