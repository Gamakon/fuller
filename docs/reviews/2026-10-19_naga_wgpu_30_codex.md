# Codex review of docs/PLAN_naga_wgpu_30.md (2026-10-19, codex exec, read-only)

1. **Blocker — the N1 rewrite changes WGSL semantics whenever the result is unused.**  
   **Claim:** Plan §2.1 says to move RHS `Emit`s/`Call`s out of Naga’s short-circuit `If`, then rewrite every `Load(v)`; it does not require a load to exist.  
   **Evidence:** Naga lowers runtime `&&` to an `If` whose accept evaluates RHS and stores it, and whose reject stores `false` ([naga lower/mod.rs:2579-2662](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/front/wgsl/lower/mod.rs:2579)). If `v` is never loaded, moving accept statements still evaluates RHS unconditionally. This changes `false && rhs()` from “do not call” to “call”. It also affects expressions in `if` conditions, loop continuing blocks, and `break_if`, which Naga lowers into the continuing block before the `break_if` expression ([lower/mod.rs:2076-2097](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/front/wgsl/lower/mod.rs:2076)).  
   **Fix:** Do not mutate control flow into eager evaluation. Preserve Naga’s `If` for execution/CPU interpretation, and reconstruct a logical node only as a reader-side projection at the load site. Add fixtures for unused values, `if (a && b)`, `continuing { break if a && b; }`, and a loop condition.

2. **Blocker — “no global store / no atomic” is not a sufficient proof that eager RHS evaluation is equivalent.**  
   **Claim:** Plan §2.1 says eager evaluation is equivalent after checking that calls do not store globals or use atomics.  
   **Evidence:** WGSL calls are explicitly emitted as statements to preserve evaluation order ([naga lower/mod.rs:3855-3862](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/front/wgsl/lower/mod.rs:3855)); Naga emits pending expressions before each call ([lower/mod.rs:3936-3959](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/front/wgsl/lower/mod.rs:3936)). A helper can have observable/non-equivalent behavior without those two effects: nontermination or a very long loop, resource reads whose evaluation is deliberately avoided, workgroup operations, or a callee that writes through a pointer argument. WGPU documents that disabling loop bounding requires proving every shader has no infinite loop ([shader.rs:26-31](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/wgpu-types-30.0.1/src/shader.rs:26)).  
   **Fix:** Remove this equivalence claim. Either retain the `If` or prove a much stronger, whole-call-graph property; the latter is unnecessary and fragile.

3. **Major — the N1 pattern is incomplete for nested logical RHSs and does not specify recursive block traversal.**  
   **Claim:** Plan §2.1 accepts only “Emits, then Calls, then Store.”  
   **Evidence:** Naga lowers RHS using a nested runtime expression context ([naga lower/mod.rs:2627-2639](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/front/wgsl/lower/mod.rs:2627)). Therefore `a && (b && c)` places another short-circuit `If` in the outer accept block, not merely emits/calls. The proposed matcher leaves it in Naga-30 shape, despite the plan’s assertion that every rendered guard traverses N1.  
   **Fix:** Prefer the non-mutating reader projection from finding 1. If retaining a normalizer, specify post-order recursive walking of `Block`, `If`, `Switch`, `Loop.body`, and `Loop.continuing`, and add exact IR-shape tests for nested RHS, loop body/continuing, `break_if`, and multiple calls/emit ranges.

4. **Major — the plan misses Naga 30 IR variants that can silently become opaque reader leaves rather than named refusals.**  
   **Claim:** Plan §1.1/§2.2 says all new variants will be explicitly refused.  
   **Evidence:** Naga 30 added `TypeInner::CooperativeMatrix` ([ir/mod.rs:834-852](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/ir/mod.rs:834)), changed `AccelerationStructure` and `RayQuery` from unit variants to variants carrying `vertex_return` ([ir/mod.rs:973-977](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/ir/mod.rs:973)), and added `CooperativeLoad` and `CooperativeMultiplyAdd` expressions ([ir/mod.rs:1903-1915](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/ir/mod.rs:1903)). Cooperative matrix syntax is lowered by the WGSL front end ([lower/mod.rs:2892-2901](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/front/wgsl/lower/mod.rs:2892)). Fuller’s reader currently turns unmatched expressions into `naga.<variant>` leaves ([reader.rs:1128-1133](/private/tmp/claude-501/-Users-andrewmorgan-Dev-gamakon-fuller/a64dc98c-8739-45f5-92d5-fe1f37ac1d88/scratchpad/n30/fuller/src/wgsl/reader.rs:1128)), rather than refusing them.  
   **Fix:** Add an early module/function feature scan that rejects every unsupported type, expression, statement, address space, builtin, and capability before reader/safety/CPU processing. Include these variants explicitly; do not depend on wildcard behavior.

5. **Major — Option B is an unsafe promise not established by the plan, and it covers more than loop/division checks.**  
   **Claim:** Plan §2.5 says “bounds only” trusted compilation is safe because renderer loops are bounded and divisors are guarded.  
   **Evidence:** `create_shader_module_trusted` is unsafe specifically because it can permit out-of-bounds behavior ([wgpu device.rs:165-187](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/wgpu-30.0.1/src/api/device.rs:165)). `ShaderRuntimeChecks` has six controls, not three: bounds, loop, ray-query, task dispatch, mesh primitive indices, and integer division ([shader.rs:6-58](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/wgpu-types-30.0.1/src/shader.rs:6)). The documented precondition for disabling integer checks also includes excluding `INT_MIN / -1`, not merely zero divisors ([shader.rs:54-57](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/wgpu-types-30.0.1/src/shader.rs:54)). Renderer guarantees do not cover externally read/model/cuneus kernels.  
   **Fix:** Keep checked compilation for any externally supplied WGSL. If retaining trusted mode for generated kernels, make it opt-in for a closed source set, construct all six fields explicitly, and add a static invariant/test proving bounds, termination, and signed division safety for every routed shader.

6. **Major — the saved-genome bar does not measure the plan’s stated compatibility property.**  
   **Claim:** Plan §2.1 says saved genes/trees/roots/holes “do not move”; §3 verifies only “481 of 481 read,” then permits re-encoding.  
   **Evidence:** The reader names locals and lets with arena handle indices ([reader.rs:470-480](/private/tmp/claude-501/-Users-andrewmorgan-Dev-gamakon-fuller/a64dc98c-8739-45f5-92d5-fe1f37ac1d88/scratchpad/n30/fuller/src/wgsl/reader.rs:470)); Naga’s short-circuit lowering appends a hidden local ([naga lower/mod.rs:2613-2625](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/front/wgsl/lower/mod.rs:2613)). A count-only read test cannot detect changed roots, holes, row identities, or different decoded behavior. Re-encoding after a count failure makes the original compatibility claim untestable.  
   **Fix:** Before upgrade, save a per-genome canonical decode containing root order, holes, row IDs, and CPU output. Require exact equality, or explicitly version/migrate the format with old→new semantic-equivalence tests. Do not call “481 readable after re-encode” preservation.

7. **Major — GPU “sign-off” is not measurable as written.**  
   **Claim:** Plan §3 says GPU tests are built but not run, while §2.5 says GPU goldens/timing decide runtime-check policy.  
   **Evidence:** Building cannot exercise Metal compilation, dispatch, mapping, timing, or values. WGPU’s default shader constructor now uses fully checked runtime checks ([wgpu device.rs:139-143](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/wgpu-30.0.1/src/api/device.rs:139)); the relevant change is runtime behavior, not type-checking.  
   **Fix:** Make execution mandatory for merge: record adapter/OS/backend, fixture and command, exact golden hashes, warm-up count, repetitions, median/p95, and a stated acceptance threshold. Retain an executable 0.20 baseline or a recorded baseline artifact; “within noise” has no meaning without one.

8. **Minor — the normalizer’s proposed `Arena::get_mut` operation is valid, but its validity tests are underspecified.**  
   **Claim:** Plan §2.1 assumes `Arena::get_mut` can rewrite `Load(v)`.  
   **Evidence:** It exists in Naga 30 ([arena/mod.rs:177-186](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/arena/mod.rs:177)). However, `Emit` ranges must contain only emit-valid expressions; result expressions are rejected ([valid/function.rs:792-835](/Users/andrewmorgan/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/naga-30.0.1/src/valid/function.rs:792)).  
   **Fix:** If any IR rewrite remains, validate every normalized module with Naga’s `Validator` and add a post-normalization WGSL write/parse/validate round trip. Test multiple `Emit` ranges around calls and `CallResult` ordering explicitly.
