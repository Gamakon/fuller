# Codex review of the §9 draft revision 2 and plan revision 5, 2026-10-21

FAIL

1. **High — §9.2.8 fuel bound is false for multi-typed frames.** It assumes `F(root) ≤ N`, but `N` sizes frames to *contain* every N-function tree; it does not cap functions expressed from all type-specific heads. Counterexample at `N=2`: types `R,T`; `R→T`, `T→R`; heads `h_R=2,h_T=1`; tree `R(T(R(t)))` has three functions. Thus the claimed `N·2^(6K)` execution and wall bounds can be exceeded. Use an actual expression-size upper bound (at least the reachable sum of head lengths), or encode a global function/fuel budget. [§9.2.8:185-190](nucleotable/docs/MultiTypedGEP_s9_WGSL_draft.md:185)

2. **High — §9.2.3 alias closure permits overlapping writes.** Validation allows identical overlapping aliases, but does not require their written members to share one ownership partition/map. A contract can declare `b` and `c` identical aliases, with `b` contiguous and `c` strided; one tree contains `store.b` and `store.c`, allowing different invocations to write the same underlying cell. Ownership must be indexed by alias class, or validation must prohibit multiple written members of an alias class unless they use the identical ownership map and write set. [§9.1.2:53-56](nucleotable/docs/MultiTypedGEP_s9_WGSL_draft.md:53) [§9.2.3:109-115](nucleotable/docs/MultiTypedGEP_s9_WGSL_draft.md:109)

3. **High — §9.2.2 read-only storage loads are not proven in range.** Contract validation requires a positive length polynomial only for written bindings. Yet every non-written storage binding gets `b[min(i,arrayLength(&b)-1)]`. With a valid declared read-only zero-length binding and `i=1`, subtraction wraps and the read is out of range. Require positive lower bounds for every binding accessed by `load.<b>`, or omit its load rows. [§9.1.2:52](nucleotable/docs/MultiTypedGEP_s9_WGSL_draft.md:52) [§9.2.2:97](nucleotable/docs/MultiTypedGEP_s9_WGSL_draft.md:97)

4. **High — B1’s stated first instantiation cannot build the worked lane kingdom.** The full target shape table includes `(1,1)`, while validation requires `W ≤` the invocation count for *every* admitted shape. Therefore the stated `partition lane 64` example is rejected before tables exist. Decide whether lane rows allow partial workgroups safely (then remove that rejection) or restrict the shape table by the contract. [§9.1.2:55](nucleotable/docs/MultiTypedGEP_s9_WGSL_draft.md:55) [§9.2.1:79-85](nucleotable/docs/MultiTypedGEP_s9_WGSL_draft.md:79) [§9.3:259](nucleotable/docs/MultiTypedGEP_s9_WGSL_draft.md:259)

5. **Closure audit.** Sound as written: §9.2.1 target/features; §9.2.4 arenas (subject to positive `L`); §9.2.5 phases; §9.2.6 uniformity/rungs; §9.2.7 loop snapshot/wrap; §9.2.9 arithmetic under its declared row meanings; §9.2.10 literals; §9.2.11 renderer totality; §9.2.12 strict atomics; §9.2.13 typed root. Unsound: §9.2.2 (finding 3), §9.2.3 (finding 2), §9.2.8 (finding 1). §9.2.5’s prior clamped-own-index and strict-atomic-load defects are resolved in revision 2.

6. **Earlier-review disposition.** All explicitly recorded earlier findings are textually addressed: guarded workgroup ownership, strict atomic loads, fixed stratum map, self-contained store guards, lane partition, row-owned clamps, counters, knob constants, transitive W closure, exact seed gating, and removal of candidate deadlines. The new defects above mean that resolution is not sufficient.

7. **Renderer/judgement and goal.** Masks, clamps, guards, `div_nz`, and shift masking are declared row semantics, not hidden renderer rewrites, provided rendering literally emits the listed templates. The plan nevertheless weakens the literal “fitness runs every expressed kernel” during repeated watchdog/device faults: it stops and reports rather than scoring that evaluation. This may be acceptable only as an external infrastructure exception, not as a kernel verdict; state it explicitly as such.
