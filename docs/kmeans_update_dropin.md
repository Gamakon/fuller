# UltraDim's k-means centroid update as an evolution benchmark

## Context

**Objective.** Evolve a faster version of UltraDim's GPU k-means centroid update that drops into UltraDim unchanged:
the same bindings, the same values within a measured tolerance, a dispatch UltraDim's Rust can issue.

**Approach.** The kernel is a problem folder of fuller's generic harness, and a module interface of the true WGSL
kingdom whose bindings are UltraDim's own. Every gene therefore expresses a kernel with UltraDim's bindings. phylu's
`wgsl_true_case_fit` evolves it in the study's regimes:

- R: from random;
- C: random search;
- P: from UltraDim's kernel toward faster.

**Status (2026-10-28).** The set-up is built and checked. The runs are not launched.

## The kernels (qdrant, read, not changed)

**A7, `update_centroids`.** In `lib/projection-voting-kmeans/src/gpu_kmeans.rs`: the kernel is at lines 654-715, its
driver `update_centroids_gpu` at 1457-1528. One invocation per (centroid c, dim j) cell, `global_id.x = c * d + j`.
It scans every assignment `v` in index order. For `assignments[v] == c` it adds `vectors[v * d + j]` with Kahan
compensation and counts it. When the count is above 0 it writes `centroids[c * d + j] = sum / f32(count)`.

- **An empty cluster is not written.** It keeps the centroid the buffer already holds: the cluster loop passes the
  same buffer it assigned against, so the old centroid.
- No normalisation: the Euclidean mean.
- The bindings, group 0:
  - 0: `vectors`, n × d f32, read;
  - 1: `assignments`, n u32, read;
  - 2: `centroids`, k × d f32, read_write;
  - 3: `params`, a `vec4<u32>` = (n, k, d, 0).
- The dispatch: `ceil(k * d / 256) × 1 × 1`.

**A6, the scatter form.** In `lib/projection-voting-kmeans/src/lib.rs`, lines 2072-2400:

- a stable counting sort by label: `block_histogram`, `cluster_offsets`, `scatter_ids`;
- then one invocation per (cluster, dim) sums its cluster's grouped ids in a fixed order (`mean_update_segmented`).

A6's own semantics differ from A7's in three ways:

- a plain sum, not Kahan;
- multiplication by `1 / len`;
- an empty cluster made zero.

The spherical variant L2-normalises the sum. Here the scatter form is written with A7's semantics, so the two forms
compute the same values (`problems/kmeans_update_segmented/segmented.wgsl`).

## The problem folders

- **`problems/kmeans_update`.** A7 is `shipped.wgsl`, verbatim. It is also the oracle: the expected centroids are A7's
  own output on this device.
  - Cases: 4 training and 4 held-out, with wide d (1,024 and 2,048), empty clusters (the last E, and at random when
    k > n), and partial workgroups.
  - Timing: 3 inputs at n = 8,192, never quality cases.
  - `planted.wgsl` is the P control: a second scan whose count guards the store.
  - `variants/` holds the tolerance probes: no Kahan, reverse order, blocks of 64.
- **`problems/kmeans_update_segmented`.** The scatter form as five entries dispatched in order:
  - `hist`, `offsets`, `starts`, `scatter`, `mean`;
  - binding 4 is a u32 scratch buffer of `n + 2k + 2·ceil(n/256)·k` words;
  - `gather.wgsl` is A7 as the `mean` entry with the other four entries empty: P's start on this interface.

## The kingdom

The kingdom's interfaces are `kingdoms/wgsl_true/mod/kmeans_update` (one entry) and `mod/kmeans_update_segmented` (five
entries plus the scratch arena), generated by `gen_tables.py`.

**The gaps found and closed, each a general change:**

1. **Fuel.** A7's loop over n needs stratum 4 (n up to 2^20). The interfaces' K is 4.
2. **No f16.** UltraDim requests no device feature, so `enable f16;` would not compile there.
   - The kingdom generated f16 for every interface.
   - `has_f16=False` now drops every f16 type, row, declaration and helper (`lib.drop_f16`).
   - The other tables are byte for byte as before.
3. **The uniform block's name.** Fields are spelled `<uniform>.<field>` (`params.x`), not only `cfg.<field>`.
4. **The reader's bindings.** The reader read v24's six bindings only. It now reads the interface's bindings from the
   kingdom's prologue: uniform, inputs, arenas, the row output, and an output owned cell by cell.
5. **A store into an output owned cell by cell.** A store at the invocation's own `global_invocation_id.x`, into an
   output of one row, now reads as the kingdom's store of the invocation's own cell (`gid.y` is 0 by the contract and
   the workgroup).
6. **Vector loads of a u32 input** were spelled as `vec4<f32>` (invalid). They now follow the input's element.

A7, the planted kernel, the scatter module and the gather module all read exactly. On the host they round-trip
through their genes and validate. 600 random modules of the two tables also validate
(`true_reader::tests::ultradim_kmeans_*`, `random_kmeans_update_modules_validate`). The device check is queued:
`examples/wgsl_true_read` runs the expressed texts against the kernels' own texts, bit for bit, on every case.

## Tolerance (measured 2026-10-28 10:08Z on Metal, M3 Max; Vulkan not yet measured)

The tolerance is a cell error of at most `(n + 2)` f32 epsilons of the expected output's RMS: Higham's γ_n, the bound
on any order of summing a cluster's points.

| probe against A7 | cases bit-exact | largest error / RMS |
|---|---|---|
| without Kahan (plain sum, same order) | 8 of 8 | 0 |
| reverse order | 2 of 8 | 1.20e-6 |
| blocks of 64 | 4 of 8 | 1.37e-6 |
| the scatter module (counting sort + segmented Kahan) | 8 of 8 | 0 |

**On Metal, A7's Kahan compensation changes no bit.** The plain sum gives A7's bits on every case
(`docs/reports/2026-10-28_metal_removes_a7_kahan.md`). Vulkan has not been measured.

Where reordering changes bits, the tolerance on those cases is 6e-6 to 4.8e-4 of the RMS, at least 4.4 times the
largest measured reordering error. Dropping one point of a cluster of 100 costs about 1e-2 of the RMS.

## Dropping a champion into `gpu_kmeans.rs`

A P run writes two files:

- `OUT/champion.wgsl`: the kernel. Its prologue is the four bindings above, unchanged, plus the kingdom's helper
  functions.
- `OUT/champion.dispatch.toml`: its workgroup size and its dispatch.

**One entry (`kmeans_update`):**

1. In `create_centroid_update_pipeline`, replace `shader_source` with the champion's text (`include_str!`). The entry
   point stays `update_centroids`.
2. Use an EXPLICIT bind group layout of the four bindings: storage read, storage read, storage read_write, uniform.
   The pipeline must not use `layout: None`. An evolved kernel may not read every binding, and an automatic layout
   then drops that binding, so `update_centroids_gpu`'s four-entry bind group would fail to create. The harness that
   scored the champion binds through one explicit layout.
3. In `update_centroids_gpu`, dispatch `ceil(k * d / WG_X)` workgroups, where `WG_X` is the champion's workgroup size x
   from `champion.dispatch.toml`. At WG_X = 256 this is today's dispatch.

**Five entries (`kmeans_update_segmented`):**

1. Create one shader module and five pipelines, one per entry point, over one explicit layout of five bindings.
2. Allocate the scratch buffer: `n + 2k + 2·ceil(n/256)·k` u32, zeroed per update.
3. Dispatch in order:
   - `hist`: `ceil(ceil(n/256)·k / WG_X)` workgroups;
   - `offsets`: `ceil(k / WG_X)`;
   - `starts`: 1;
   - `scatter`: `ceil(n / WG_X)`;
   - `mean`: `ceil(k·d / WG_X)`.
4. Use one compute pass per entry, or one pass with the dispatches in order: wgpu orders storage writes between
   dispatches in a pass.

**The work guard.** Every candidate ran under the work guard, its dispatch split into submits of whole workgroups.
UltraDim runs one dispatch. The split changes neither values nor order: each cell's invocation runs alone. It changes
the timing by the submits' overhead, which the yardstick pays too, and the champion's re-time is against the
yardstick under the same split.

**The measured cap (2026-10-31).** The machine's cap (1.7e8 node executions a submit) left the scatter form untimed:
its `mean` entry is bounded by 171,993,344 a workgroup at the timing input. A7's own timing (1,024 workgroups of
125,841,920 in 1,054.9 GPU ms: 1.22e11 a second) gives, by the cap's own rule (a submit at most 0.1 s over a safety
factor of 10), `work_guard::CAP_M3_MAX_MEASURED_NODE_EXECUTIONS_PER_SUBMIT` = 1.22e9. A P run times its yardstick
under the machine's cap first and raises the executor's cap only when that measured rate justifies it; an exact
kernel still over the cap is untimed (no speed credit), never an error. The per-submit GPU wait bound stays.

## Timing rules (2026-10-31)

- **The yardstick is UltraDim's own A7 text**, timed as written. The kingdom's expression of A7 is timed against it at
  the start of every P run (the cost of reading and rendering; measured 0.579 the other way round, 2026-10-31 03:38Z:
  the expression inlines A7's `let`s, so `idx / d` is computed on every one of the n trips, and it clamps every load
  with `min(i, arrayLength - 1)`). Fixed the same day: every kernel is spelled through the share pass, which binds
  a loop-invariant, context-free subtree at function scope (`true_share::Share::share`); a trip of A7's loop then
  spells the source's arithmetic exactly (1 `*`, 4 `+`, 3 `-`, no `/` or `%`; before: one `/` and one `%` more),
  the two index clamps apart (the source's are wgpu's bounds checks), with the source's bits on the CPU executor.
- **Speed is timed unsplit**, one dispatch a step exactly as UltraDim dispatches it, for an exact kernel whose run is
  bounded by at most twice A7's; above it a kernel gets no speed credit. Quality cases keep the work guard's splits.
- **A warm-up pair** is timed and discarded before every timed comparison (each A/A set, each kernel's pairs), as the
  Futhark study discarded its first process.
- **Runs a side**: a side takes the fastest of enough runs to add up to at least 200 ms of the yardstick's time (A7
  unsplit is about 15 ms a run), so the GPU's clock states do not split the ratios (set 1 of the 03:38Z gate had pairs
  at 0.516, 0.582 and 0.596 between pairs at 1.000).
- **A loop's trip count is bounded by the problem's sizes** (kingdoms/wgsl_true/loops.py `size_bounds`): n, k, d, a
  literal 1..=4096, and `+ * / >> min max` of them. A free literal or a load can no longer bound a loop, so every gene's
  work bound follows from the sizes (the 6 smoke-run mutants that the guard could not split had a bound of
  4,218,022,233 or `assignments[..]`, capped at 2^24 trips).
