# CHECKLIST: what every Futhark problem of the one runner gets

## Context

**Objective.** One runner, `examples/futhark_evolve.rs`, evolves every Futhark problem (`fuller::futhark_sig::PROBLEM_NAMES`: reduce, scan, histogram, pathfinder, kmeans, a7), and every problem gets the same machinery: a named fitness scheme with the correctness gate, the slope check, interleaved one-upload timing with the timing-case output check, the ring canvas, the operator mix with per-operator logging, and the runner standard (`docs/STANDARD_runners.md`: stream, `killme.trigger`, checkpoints, hall of fame, ledger, `aa_gate.tsv`).

**Approach.** The table below has one row an item and one column a problem. A cell names the code or the test that proves the item for that problem, or says `not yet: <reason>`. It was filled from the code (each runner path read), not from memory, and the cheap claims are checked by `futhark_sig::tests_checklist` (every problem loads, has a default scheme, its reference and planted slowdown build, fit the layout and are exact on every stored case through the host interpreter, it has a timing input of the declared shape; the table has a column for every problem and a row for every item, and the not-yet count below equals the table's).

**What is new (2026-11-03, step 4 of `docs/PLAN_futhark_kingdom.md`).** A7, the matrix kingdom, is a problem of this runner (`--problem a7`): its view (`kingdoms/futhark/view.tsv`, `shape matrix`) loads through the signature family's loader; its signature is the interface's nine matrices; the host interpreter covers the matrix rows (`transpose`, `matmul`, `map` and `map2` over rows, the row functions); its reference, winner and planted slowdown are exact on the stored cases through the interpreter and through `futhark c`; its e-graph is the generator's (`kingdoms/futhark/egraph.*`) through the same bridge. `examples/futhark_a7_evolve.rs` and its loop (`fuller::futhark_search`) are DEPRECATED: they stay, print a deprecation line, and keep their tests passing (phylu's `evolve::shape_typed` is built on them).

**Status.** Everything in the table that needs no GPU is done and tested. **12 cells say not yet**: the slope check is not yet run for reduce, scan and a7 (it is the GPU's; k-means has none: no stored answers); reduce and scan have no test split among their stored cases; the GPU timing paths are not yet run for kmeans and a7 (the C batch driver is i32 only, so their path is `--eval rust`); reduce, scan, kmeans and a7 have no ring-canvas pool; the measured GPU cost (`futhark_gpu::measure`) is not wired into this runner for a7. The commands that close them are at the end. A7's slope check already passes on the C path at 30 random genes (its cell).

## What closes the not-yet cells (the GPU's, when it is free)

```
# the slope check, then the gate, for each problem (a7 shown; reduce, scan, kmeans alike)
cargo run --release --features gpu,wgsl --example futhark_evolve -- --problem a7 --check --eval rust --out /private/tmp/claude-501/fbench/a7_check
# the first A7 run on the one runner: from the published program toward faster, the timed pairs, aa_gate.tsv
cargo run --release --features gpu,wgsl --example futhark_evolve -- --problem a7 --regime P --eval rust --evaluations 2000 --minutes 60 --seed 1 --out /private/tmp/claude-501/fbench/a7_P_s1
# kmeans, the same two commands with --problem kmeans
```

The pools (ring canvas) are written by `examples/futhark_pool.rs` from the benchmarks and a model's programs; the test splits of reduce, scan and kmeans are added to their `make_cases.sh`. The measured GPU cost stays a decision: a new `futhark_sig` scheme that reads `futhark_gpu::measure` beside the timed pairs, never a change to an existing scheme (`docs/FITNESS_SCHEMES.md`).
