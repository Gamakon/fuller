# WGSL on the typed gene (fuller side)

Code: `src/wgsl/typed_gene.rs`. Design: `nucleotable/docs/MultiTypedGEP.md` (rev 4).
Example: `examples/wgsl_typed_roundtrip.rs`. Dated 2026-10-20.

## Purpose

A WGSL kernel is read by the safe reader (`safe_reader.rs`) into a typed tree
of the safe kingdom (`kingdoms/safewgsl`). The typed gene is the genotype of
that tree in the multi-typed GEP core (`typed_gep.rs`): one head and one tail
per output dual, and constants held in per-dual pools. Encoding then
expressing returns the same tree, and rendering it returns the same text.
A tree that does not encode, express or render back is a named `Gap`, never
a substitute.

## Pipeline

WGSL text -> `read_safe` (tree, interface `Role`, and the module's extended
kingdom when it declares aggregate types) -> `encode` -> `Encoded` -> `express`
-> tree -> `render_tree_with` -> text -> naga validation.
`round_trip(alphabets, kingdom, text)` runs all of it and returns an `Outcome`:
`NotRead`, `Unrenderable`, `Gap`, or `Expressed { tree_equal, text_equal, valid }`.
`through_the_gene` checks the tree alone.

## Alphabet, one per interface

`Alphabet::new(kingdom, role)` is the symbol table of one kernel interface:

- every row of the kingdom (a polymorphic row is one symbol per output dual);
- the interface's per-kernel rows (loads and stores of its bindings);
- the capability rows (what the interface's bindings allow: a load of every
  storage binding, atomics, textures), not only what the reference uses;
- the `<type>.value` duals and rows (`agg.zero`, `agg.at`, `agg.member_<m>`)
  of a module that declares arrays or structs.

The rows become a `KingdomContract` (`relations_from_rows(...).check()`): roots
`kernel.safe` and `kernel.module`, one output per symbol, ordered signatures.
`Alphabets` caches one alphabet per interface; its key includes the value duals.

## Terminals: own.* and const.*

Every dual has a real terminal, so a position the search leaves unspecified is
never filled with a stand-in.

- `own.*` rows render as their own text: the thread's own row, column or cell,
  a thread id's axis, an empty block, the default grid, the empty kernel whose
  epilogue stores the thread's own cell. About 68 rows, generated by
  `gen_tables.py`.
- `const.*` rows are the constants of the dual forms no literal reaches
  (matrices, hashes, fixed point, sign, vectors of any lane form).
- Literals are `literal.*` rows. A constant leaf is any of these two families.

Rows are never edited by hand in the TSVs; `kingdoms/safewgsl/gen_tables.py`
writes them.

## Constants: exact bit patterns in C_T

A constant leaf holds an index into `C_T`, one append-only pool per dual with
`pool[0] = 0`. Each entry is the constant's exact `u32` bit pattern: an f32's
bits, a u32, an i32's two's complement, a flag's 0 or 1, an f16's 16 bits.
`const_bits` and `const_value` convert both ways and reject a value the dual
cannot hold. `Tree.konst` is an `f64` (exact for every u32 and i32), so no
integer is limited to 2^24 and no f32 is rounded on the way. Text prints an
f32-exact value as an f32.

## Head and tail per dual

The tree fixes the layout: `required_heads` gives the head length `h_T` each
dual needs, `write_back` places the tree into the cells, and `express` is the
FIFO walk with one frame per dual. A head holds functions and terminals; a tail
holds terminals only. A `Dc_T` domain per constant dual indexes `C_T`. A
function in a tail is rejected by the host. An explicit layout (`encode_into`)
holds what fits and names what does not.

## What stays unread, by reason (harvest, 4,332 files)

Reasons in naga or in the file, not in the kingdom:

- 560: naga lacks the language extension `texel_buffers`.
- 394: naga lacks `chromium_experimental_subgroup_matrix`.
- 57: naga lacks `multisampled_array_textures`.
- 277: no compute entry point.
- 176: naga stops at "expected global item" (the file is not plain WGSL; causes not individually checked).
- 40 + 35: identifiers the file never defines (`print`, `scalar`).
- 47: naga cannot give an expression a concrete type.
- 40: naga rejects pointer arguments in a storage address space.

Reasons in our software (aggregates, open):

- 43: a helper returns an aggregate value no register holds.
- 38 + 23 + 22: a whole-aggregate store (`store.buffer.*`) has no row.
- 22: nested statement-level failures (attention kernels).
- 36: f16 matrix uniform loads; 18: workgroup array of struct arrays;
  18: a local of an aggregate dual with no register kind;
  about 50: private variables with initialisers.

The aggregate rows still to add: registers for aggregate and f16-matrix
locals, `with_*` updates, whole-value stores, aggregate returns, constructors
read as chains.

## Rules that apply

A gene is valid by construction: no repair, rejection, substitution or
fallback. A gap says "our software has a bug: ..." and names the dual or row.
